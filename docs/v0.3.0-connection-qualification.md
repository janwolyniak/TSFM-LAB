# v0.3.0 live connection qualification worksheet

Prepared on 2 November 2026 from the maintained connection implementation.
**No live qualification was performed to prepare this worksheet.** The published
release and its limits are recorded in the [release notes](release-v0.3.0.md).
Offline evidence remains in the [S5 record](s5-connections-verification.md);
this document does not promote those tests to live-provider or native-OS passes.
For this follow-up, the owner authorizes the offline protocol repair only and
keeps all live-provider and native-vault checks pending. No credentials, new API
keys, paid requests or browser sign-in are authorized by this worksheet.

## Scope before execution

Record the exact source/wheel identity, OS and architecture, Python and optional
connection-runtime versions, selected route, destination, assistant model,
storage mode and authorized request budget. Use disposable synthetic inputs and
an isolated connection metadata directory outside experiment outputs. Do not
reuse or alter an existing account connection without authorization.

The [contribution workflow](../CONTRIBUTING.md) governs paid requests, dependency
installation, protected credential writes and browser authorization. This
worksheet supplies a procedure, not permission or account access. Keys must be
entered through the app's hidden prompt; never put them in shell arguments,
reports, screenshots, source files or outgoing assistant context. A connected
Codex or Platform account does not establish a TSFM-LAB grant or provider credit.

Use [connection management](connections.md#setup) to add/select the route,
discover models, choose one explicitly and review the exact outgoing request.
`tsfm connections list --json` reads nonsecret saved metadata only; a saved
profile or available connector is not evidence that authentication works.
`tsfm connections manage --state-directory TASK_DIR` isolates a constant-check
session. For full assisted flows in that same isolated state, instantiate the
maintained `TerminalSession` with an explicit
`connection_manager=ConnectionManager(StateStore(task_directory))` and disposable
workspace/preferences. The ordinary `tsfm ui` does not inherit the other command's
`--state-directory`; do not silently switch to the user's default connection store.

## Requests and acceptance beyond a smoke

Default limits are 30 seconds, 32 KiB input, 256 KiB received bytes and 64 KiB
accepted text per operation, with no automatic retries. The constant connection
check requests 32 output tokens on key/local routes. ChatGPT plan usage omits
that output-token field; local byte/time bounds are not a monetary cap.
An interrupted or rejected operation may still consume provider usage.

One successful constant reply proves only that route's smoke. For the complete
historical/future assistance path on a selected route, reserve **five separately
approved generations**: constant check, historical draft, future draft,
historical explanation and future explanation. Draft/explanation previews use
2,048 requested output tokens per operation on key/local routes; the same plan
restriction applies. Every Ollama generation additionally performs model
inspection, which is not itself a generation request.

Use tiny bundled synthetic data and existing or newly created offline baseline
records. For each operation, record:

- The exact selected destination/model, local limits and consent result.
- For drafts: schema 1 historical or schema 2 future, local validation outcome,
  preserved selected mode and explicit choices, and required ordinary run review.
  Do not execute a draft merely because the provider labels it ready.
- For explanations: local fact validation, retained evidence IDs and units;
  future accuracy remains unavailable with `future_actuals_absent`. Future
  context contains metadata only, not observations, predictions or value summaries.
- A declined preview sends nothing; a changed destination/model invalidates the
  old preview. Cancellation returns control with a truthful status. A separate
  real cancellation request needs its own request budget and may incur usage.
- No credential or account token appears in retained artifacts or diagnostics.
  Use existing fake fault-injection tests for malformed output, quota/auth errors,
  reflected secrets and timeouts; do not deliberately exhaust a live account or
  send real credentials to a reflection service to reproduce those cases.

## Native protected storage and browser checks

Execute the native storage contract independently on each supported OS. The
implementation selects `keyring.backends.macOS.Keyring`,
`keyring.backends.SecretService.Keyring` or
`keyring.backends.Windows.WinVaultKeyring` directly. Availability on one OS does
not establish the other two. Record exact OS/backend/runtime versions.

With authorization for disposable entries, put a synthetic credential bundle
under a fresh task-owned reference in service `TSFM-LAB.connections.v1`, compare
the retrieved value privately and retain booleans only. Restart the isolated
test process, read it again, delete only that task-owned reference and verify
absence. Never enumerate, export, rewrite or delete pre-existing vault entries.
Record an unavailable/denied native backend as such; injected-backend tests are
offline evidence. Do not lock or reconfigure the user's OS vault to manufacture
an error. Confirm an explicit session-only selection has no persistent secret;
failure must not create a plaintext credential file.

For ChatGPT browser qualification, a human selects and authorizes the real account
in the official browser flow. Check the loopback listener is bound first, browser
cancel/timeout leaves no usable partial session, successful identity/scope checks
permit discovery, and disconnect disables local use even if remote revocation
cannot be confirmed. Retain only redacted outcomes, never callback URLs, cookies,
authorization codes, tokens or the full authorization URL. Exercise restart and
refresh when the real lifecycle permits; do not edit protected tokens or falsify
expiry to claim a live refresh pass. Record refresh separately if not observed.
Repeat native browser/terminal integration on the actual advertised platforms,
including Windows Terminal where required by [S8](windows.md).

The [public documentation workflow](public-documentation.md) owns S7. Once the
owner selects a public host/base URL and authorizes deployment, rebuild the
curated artifact for that URL, inspect its manifest/content, deploy only those
outputs and retain the deployed artifact identity. Keep the source repository's
visibility unchanged unless separately requested.

From outside the authenticated host session, check final HTTPS reachability,
redirects, canonical/social/structured URLs, all internal links, citation/version
text, `robots.txt`, sitemap and any infrastructure authentication/noindex rules.
Record anonymous access separately from an owner's authenticated preview.
Reachability and crawl eligibility do not guarantee indexing or AI citations.
No public-host or deployment result was established by preparing this worksheet.

## Evidence fields and completion

Keep one result per route/destination/model/platform, with date, exact application
revision/wheel hash, environment, granted scope and limits, nonsecret endpoint
and model identifiers, request counts, accepted/rejected response status,
draft/explanation outcomes, restart/cancel/disconnect results and evidence-file
hashes. Use `passed`, `failed`, `blocked` or `not_run`; preserve reasons and omit
secrets, raw account identifiers and private input paths. For storage/browser
checks, retain separate native-platform rows. For documentation, retain the public
URL, deployed artifact identity and anonymous checks. Mark release-plan items only
when their complete stated acceptance criteria have supporting executed evidence.
