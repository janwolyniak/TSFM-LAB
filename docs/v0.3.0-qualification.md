## Qualification implementation

The source/wheel builder requires the new model and portability modules, runtime
constraints, fixtures, public guide sources and verification records. Its metadata
audit keeps platform dependencies optional only under an explicit extra. The
stdlib-only marker parser accepts bounded conjunctions of the maintained extra
and Windows selectors; OR, unknown/duplicate selectors and malformed markers
cannot disguise optional-runtime packages as numerical-core dependencies.

The installed verifier requires `--wheel` and compares installed package and
metadata bytes with that exact wheel before running workflows. It refuses source
checkout leakage, editable installs, inherited system site packages and
nonisolated Python execution. Every child has a deadline and explicit UTF-8
output handling. Model, provider, secret-vault and kernel modules are blocked
inside the disposable workflow probes, including the new TOTO runtime.

  precise checkpoint/runtime/profile metadata; no cache creation during browsing.
- Bundled fixture generation checked by independent arithmetic; two historical
  baselines, four windows and 16 forecast cases each; history and comparison.
- CSV/JSON/Parquet roundtrips and overwrite refusal; invalid configuration
  rejection before artifacts; four-case costed OHLC accounting and detached reload.
- A schema-2 native-point metadata fixture with inert weights, proving record and
  export behavior without claiming TTM inference.
- All five usage categories, original-unit values, metadata-only relabelling and
  detached reload.
- All seven connection routes through fake transports: model discovery, reviewed
  drafts and explanations, 21 generation requests and 31 protocol calls. No
  credentials remain after disconnect; profile metadata remains inspectable.
- First-launch preference roundtrip/restart/cancel with spaces and Unicode paths;
  real managed historical and future **baseline** workers; exact seven/eight
  artifact sets and visible output locations.
- Four future rows on the next timestamp grid, unavailable accuracy with
  `future_actuals_absent`, comparison/finance refusal before accounting, detached
  CSV/JSON/Parquet exports after removing the source input, and unchanged records.
- Clean managed worker completion; optional-import and actionable missing-runtime

For the isolated installed invocation and native executable paths, follow the
[release workflow](releasing.md#verify-an-ordinary-installation-outside-the-checkout)
and [Windows guide](windows.md). Build from the committed qualification revision,
retain the builder/identity/verifier JSON next to the exact artifacts, and do not
use a same-version installed package as a substitute for byte identity.
Unrelated untracked local input can make the builder's dirty flag true; the
separate identity check must establish the packaged files' committed bytes.

## Remaining release gates

- Representative installed-runtime/import and bounded real CPU inference for
  the new TTM behavior and TOTO 2 remain pending by owner instruction. Guided
  missing-weight download/cache repeat, actual model loading, live model progress
  and cancellation must still be qualified on the selected runtimes.
- Native Windows 11/Windows Terminal, drive/file-lock and private-console Ctrl+C,
  native vault/browser connections and optional-model checks require native hosts.
  Local pure-path/simulated platform cases are not native execution evidence.
- The nine-job Linux/macOS/Windows Python 3.11-3.13 matrix is configured. Hosted
  jobs are blocked before execution by GitHub account billing/spending limits.
  For example, [run 40895398834](https://github.com/janwolyniak/TSFM-LAB/actions/runs/40895398834)
  produced pre-start failures, not test results. No spending settings changed;
  the v0.2.0 CI exception does not qualify v0.3.0.
- Live provider/endpoint behavior and native protected credentials remain
  unqualified. Fake routes prove the exercised protocols and local boundaries.
- The public documentation artifact is prepared locally with a candidate URL;
  host/URL confirmation, deployment, public reachability and crawl checks remain
  separate. No repository visibility, hosting or publication setting changed.
- Versioning, maintainer review/integration, release tag/assets and any package
  publication remain separate from feature commits. S3, S6, S7, S8 and S9 items
  needing the above evidence remain open in the release plan.
