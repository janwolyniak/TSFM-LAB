On 2 November 2026 the owner authorized isolated runtime installation, the six
selected checkpoint downloads and bounded local CPU inference. The earlier
offline-only restriction was lifted for these checks. This record describes
synthetic integration checks; it establishes no accuracy or trading advantage.

The [compact evidence](v0.3.0-model-qualification.json) binds these checks to the
**published v0.3.0 wheel**, SHA-256
`04eef833eb1113254485975c916c5ae61f44f18a72c9ad12998bce869f5b867a`,
and verified committed source `9ad508c580243d58df18d29119641e92e2b46e81`.
The source archive identity is
`65a75503a36071250f0db3b417d85c125bb8650211b6cfb74edec6baf48a27d7`.
All 118 installed package files matched the wheel before execution. These are
ordinary isolated installations, with no editable/source imports. Recorded

All ten recorded case groups passed. TTM checks use each selected full native
horizon; TOTO crosses multiple 32-step decoding blocks. Every case checks:

- Exact config/weight SHA-256 identities, strict loading, correct output count,
  timestamp grid, finite outputs and actual point-statistic labels.
- Exact agreement with an explicit pinned native call and its documented inverse
  projection into original units. No arbitrary affine or cross-horizon
  invariance is assumed.
- Identical cached replay, target-only perturbation causality, same-context
  historical/future forecasts and a new successful run after injected failure.
- Managed post-forecast cancellation and separately labelled injected failure,
  truthful manifests, reaped children, and unchanged saved bytes during export.

The six new weight files total **34,056,848 bytes**. Each was acquired once,
through real fresh-cache guided review/preparation/execution. Retained stage
records cover cache, download/bytes, verification, preparation, native loading,
forecasting, evaluation and saving. The existing 512/96 checkpoint was reused
from a pre-existing cache without another weight download.

A separate ordinary TOTO worker was cancelled at its observed **loading** stage,
without a qualification pause. It reached the normal termination escalation,
exited with code -15, left a cancelled manifest and was reaped. A subsequent
ordinary run completed with exit code zero. The post-forecast harness tests use
an explicit callback pause after actual native inference; they do not claim
interruption inside a native tensor operation. Injected callback failures are
not represented as native-runtime failures.

Three additional probes used the ordinary frozen-wheel core/CLI installation
with Torch absent and optional model/provider imports blocked. They reloaded
**57 completed records in 17 groups** and produced **171 CSV/JSON/Parquet exports**,
including guided seven-artifact historical records and eight-artifact future
records. Source fixtures were unavailable, checkpoint/model access was blocked,
and saved bytes were unchanged. Future accuracy remained unavailable because
future actuals were absent.

## Runtime diagnosis and constraints repair

The documented `scipy==1.15.3` candidate installed and passed dependency metadata
checks, but importing its PROPACK extension failed under the tested macOS 27
loader. SciPy 1.15.2 reproduced the same `__thread_bss` zero-fill diagnostic.
This failure is also discussed in [SciPy issue 25635](https://github.com/scipy/scipy/issues/25635);
this project's diagnosis uses its separately retained local traces.

**SciPy 1.14.1 passed actual TOTO imports and all native cases on Python 3.12.11
and 3.13.6.** It already satisfies the frozen wheel's `>=1.14,<1.16` guard;
no binary or adapter/checkpoint guard was patched. The maintained
[optional-runtime constraints](../requirements-toto2.txt) now select this tested
version. Success with the permitted replacement does not retroactively qualify
the failed original 1.15.3 candidate.

The TTM runtime, TOTO runtimes and shared environment all passed `pip check`.
Shared installation retained Torch 2.8.0, NumPy 2.1.3, Transformers 4.56.0,
Hub 0.35.3, TOTO 2.0.0 and Granite 0.3.4. Full dependency-closure hashes and exact
observed model-package versions are retained in the JSON record. The initial
extra-constrained TOTO attempt also exposed a development-only conflict:
`requirements-dev.txt` pins Packaging 25 while Lightning 2.4 requires Packaging
below 25. The published model-specific installation guide does not apply that
development constraint.

## Reproduction and limits

The driver never installs or downloads. Supply an already acquired exact
checkpoint/cache and a new disposable evidence directory, using the ordinary
verified wheel environment outside the source checkout:

```sh
"$MODEL_ENV_PYTHON" -I scripts/qualify_v030_models.py \
  --wheel "$MODEL_WHEEL" --expected-version 0.3.0 \
  --profile 52-16-ft-r2.1 --cache-dir "$MODEL_CACHE" \
  --output-dir "$NEW_EVIDENCE_DIRECTORY" --timeout-seconds 300
```

Repeat for each named profile or `toto-4m` in its supported Python environment.
The original v0.3.0 controller hash is recorded in the evidence JSON. After these
runs the driver gained the explicit `--expected-version` selector, defaulting to
0.3.0, so independently identified 0.3.1 wheel replays can use the same checks.
That interface addition does not relabel the original runs or their driver hash.
New patch-wheel evidence must identify its own exact wheel and controller bytes.

Only the recorded native platform/Python/profile cases are qualified here.
Native Windows interactive and live-provider/native-vault checks remain separate,
owner-deferred work. Larger unexecuted TTM profiles retain their own status.
Historical results keep their saved verification snapshots; adding these project
checks does not rewrite old records or change their numerical identities.
